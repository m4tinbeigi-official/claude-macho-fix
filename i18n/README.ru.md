# Claude Desktop — исправление ошибки "Malformed Mach-o file" / нарушения целостности ASAR (macOS)

🌐 **Читать на другом языке:** [English](../README.md) · [فارسی](README.fa.md) · [العربية](README.ar.md) · [中文](README.zh.md) · [Español](README.es.md) · [हिन्दी](README.hi.md) · [Français](README.fr.md) · [Русский](README.ru.md) · [Português](README.pt.md) · [Deutsch](README.de.md) · [日本語](README.ja.md)

Исправление и объяснение двух связанных между собой сбоев, которые могут возникать в **Claude
Desktop для macOS** после того, как `app.asar` (упакованный код приложения Claude Desktop) был
изменён — будь то сторонним патчем, плагином, ручным вмешательством
или чем-либо ещё, что распаковывает и заново упаковывает пакет приложения.

Это **не** проблема какого-то одного конкретного патчера или инструмента. Любой проект, который
извлекает, редактирует и переупаковывает `app.asar` Claude Desktop, может вызвать одну
или обе эти проблемы, если не обработает корректно два нюанса, специфичных для macOS/Electron.
Этот репозиторий документирует обе первопричины и содержит
скрипт для исправления в одну команду.

просто молча не открывается.

## Первопричины

### 1. Нативный бинарник оказался упакован *внутрь* `app.asar` вместо того, чтобы остаться распакованным на диске

Electron-приложения хранят определённые файлы — нативные модули (`*.node`), динамические
библиотеки (`*.dylib`) и прочие нативные вспомогательные бинарники — физически
распакованными на диске рядом с `app.asar`, в соседней директории `app.asar.unpacked/`.
Всё остальное лежит упакованным внутри единого файла-архива `app.asar`.

Если скрипт переупаковки решает, что оставить распакованным, на основе **жёстко заданного**
списка расширений файлов (частый паттерн: `{*.node,*.dylib,spawn-helper}`),
то любой нативный бинарник, который не подпадает под этот список — например, вспомогательный
бинарник для вкладки Claude Code, поставляемый без одного из этих расширений, — оказывается
упакован *внутрь* архива. Запись в архиве — это не полноценный, самостоятельно
исполняемый файл: ОС не может выполнить `exec()` над диапазоном байт внутри другого
файла и получить рабочую программу. Когда Claude Desktop пытается запустить
такой бинарник, ОС считывает не выровненный по границам файла кусок байт и сообщает о
повреждённом/некорректном Mach-O — отсюда и сообщение "Malformed Mach-o file".

**Исправление:** не задавайте список распаковки жёстко. Вычисляйте его динамически, исходя из
того, что *уже* распаковано рядом с исходным `app.asar`, ещё до того, как вы что-либо трогаете,
и используйте этот же набор при переупаковке. См.
[`lib/unpack.js`](../lib/unpack.js) для готовой к использованию реализации, и после переупаковки
проверьте, что ничего не пропало.

### 2. Повторное подписание без предварительного удаления устаревших вложенных подписей

Изменение файлов внутри `app.asar` делает недействительными вложенные подписи кода
уже подписанных вложенных пакетов, поставляемых вместе с ним
(`Contents/Frameworks/*.framework`, вспомогательные приложения `Contents/Frameworks/*.app`,
`Contents/Helpers/*`, встроенные XPC-сервисы и т. д.) — но не удаляет эти
устаревшие подписи. Запуск `codesign --force --deep --sign -` поверх них
может привести пакет в несогласованное состояние:

```
$ codesign --verify --deep --strict /Applications/Claude.app
/Applications/Claude.app: nested code is modified or invalid
file modified: .../Claude Helper (GPU).app
file modified: .../Electron Framework.framework
...
```

Сам шаг *подписания* сообщает об успехе ("replacing existing signature") —
сбой проявляется только при `--verify`, что легко упустить, если не проверять это явно.

**Исправление:** сначала выполните `codesign --remove-signature --deep`, чтобы удалить все
вложенные подписи, а *затем* подпишите заново с нуля. См.
[`lib/macos.js`](../lib/macos.js).

### 3. Встроенный в Electron механизм проверки целостности ASAR ("fuse")

Именно это вызывает Симптом 2 (приложение вообще не запускается). В Electron есть
"fuse" (переключатель, задаваемый на этапе сборки) — `EnableEmbeddedAsarIntegrityValidation`,
который, если включён, встраивает ожидаемый SHA-256-хеш `app.asar` прямо в
бинарник **Electron Framework**
(`Contents/Frameworks/Electron Framework.framework/Electron Framework` в
macOS — *не* основной исполняемый файл приложения в `Contents/MacOS/`, и *не* какой-либо
ключ `ElectronAsarIntegrity`, который вы можете найти в `Info.plist` — это отдельный, не
связанный с этим устаревший механизм, который некоторые инструменты сборки также иногда записывают).

После того как `app.asar` пропатчен, встроенный хеш перестаёт совпадать, и
Electron аварийно завершает работу при запуске вместо того, чтобы корректно деградировать.

Пересчитать и вручную пропатчить этот встроенный хеш непрактично — он является
частью специфического бинарного формата "fuse wire" наряду с несколькими другими флагами.
Поддерживаемый способ исправления — полностью отключить этот fuse с помощью собственных
инструментов Electron, [`@electron/fuses`](https://www.npmjs.com/package/@electron/fuses):

```bash
npx --yes @electron/fuses write --app /Applications/Claude.app EnableEmbeddedAsarIntegrityValidation=off
```

Это изменяет бинарник Electron Framework, что делает его подпись недействительной — после этого
необходимо заново подписать весь пакет целиком (исправление из первопричины №2
как раз это и делает).

## Быстрое исправление — уже есть сломанная установка?

Если вам просто нужно починить уже установленный `Claude.app` (не обязательно
знать, какая именно из указанных выше проблем у вас проявилась — это исправление устраняет обе):

### В один клик (без терминала)

1. [Скачайте этот репозиторий](https://github.com/<your-username>/claude-macho-fix/archive/refs/heads/main.zip) и распакуйте его.
2. Дважды кликните по файлу **`Fix Claude.command`**.
3. Откроется окно терминала, которое проведёт вас через каждый шаг и предложит
   перезапустить Claude Desktop по завершении.

macOS может выдать предупреждение, что файл от неопознанного разработчика, при первом
запуске — щёлкните по нему правой кнопкой мыши и выберите **Открыть**, чтобы обойти это один раз.

### Одна команда (терминал)

```bash
curl -fsSL https://raw.githubusercontent.com/<your-username>/claude-macho-fix/main/repair.sh | bash
```

Либо склонируйте репозиторий и запустите скрипт локально:

```bash
git clone https://github.com/<your-username>/claude-macho-fix.git
cd claude-macho-fix
./repair.sh
```

`repair.sh` автоматически находит `Claude.app` (или `Claude Beta.app`) в стандартных
местах установки, завершает его работу, если он в данный момент запущен, проходит через все
шаги исправления с понятным выводом об успехе/неудаче каждого шага, проверяет результат и
предлагает перезапустить приложение за вас. Передайте путь явно, если ваше приложение
находится в нестандартном месте:

```bash
./repair.sh "/path/to/Claude Beta.app"
```

`repair.sh` **не** изменяет никакой функциональности или контента Claude Desktop —
он лишь отключает fuse проверки целостности и заново подписывает пакет.
Его безопасно запускать, даже если вы не уверены, какой именно симптом у вас проявился, и безопасно
запускать многократно. Если у скрипта не окажется прав на запись в пакет приложения, он
предложит запустить его повторно с `sudo`.

## Если вы пишете собственный патчер

Если вы разрабатываете инструмент, который патчит `app.asar` (для локализации, изменения темы,
плагинов или чего-либо ещё), вы можете изначально избежать поставки этих ошибок своим
пользователям. Этот репозиторий включает готовые к использованию, документированные модули:

- [`lib/unpack.js`](../lib/unpack.js) — вычисляет корректный glob-шаблон для `unpack`,
  используемый в `createPackageWithOptions` из `@electron/asar`, динамически, исходя из того,
  что уже распаковано. Готовая замена для жёстко заданного списка расширений.
- [`lib/macos.js`](../lib/macos.js) — корректно переподписывает пакет приложения macOS
  (сначала удаляет вложенные подписи, затем подписывает с нуля, затем проверяет).
- [`lib/fuses.js`](../lib/fuses.js) — отключает встроенный в Electron fuse проверки
  целостности ASAR с помощью `@electron/fuses`.

Все три модуля — обычный Node.js, с минимумом зависимостей и не привязаны к какому-либо
фреймворку — они не делают никаких предположений о том, *для чего* вы патчите Claude Desktop,
а лишь о том, что вы переупаковываете `app.asar` и затем заново подписываете пакет.

```js
const { computeUnpackGlob, collectUnpackedRelativePaths } = require('./lib/unpack');
const { reSignMacApp } = require('./lib/macos');
const { disableAsarIntegrityFuse } = require('./lib/fuses');

// 1. Before extracting/patching, snapshot what's currently unpacked:
const unpackGlob = computeUnpackGlob(asarPath);

// 2. ...extract, patch, repack app.asar using `unpackGlob` for the `unpack` option...

// 3. Disable the integrity fuse and re-sign the whole bundle:
await disableAsarIntegrityFuse(appPath);
reSignMacApp(appPath);
```

## Почему это не баг Claude Desktop

Чтобы быть предельно ясным: Claude Desktop в данном случае ведёт себя правильно. Fuse проверки
целостности ASAR в Electron и подписание кода в macOS *призваны* отклонять изменённый
пакет приложения — в этом весь их смысл. Этот репозиторий существует для людей, которые
осознанно решили пропатчить собственную локальную копию Claude Desktop
(для доступности, локализации или по другим законным личным причинам) и
хотят, чтобы их патч также корректно отключал/обновлял механизмы, которые в противном случае
блокировали бы его запуск, вместо того чтобы оставлять приложение в наполовину рабочем состоянии.
